# 학업 플래너 — 설정 안내

과제 하나를 정하고 10분만 시작하는 데 초점을 맞춘 학업 플래너입니다. GitHub Pages에 올리는 PWA이며, Firebase를 연결하면 크롬북·아이패드·휴대폰 사이에 기록이 동기화되고, 오프라인에서도 열리고 입력할 수 있습니다.

Firebase를 연결하기 전에도 **로컬 모드**(이 기기에만 저장)로 바로 쓸 수 있습니다. 먼저 1단계만 해서 써 보고, 마음에 들면 2~5단계를 진행해도 됩니다. 로컬 모드에서 쓴 기록은 나중에 설정 화면의 '로컬 기록 가져오기'로 계정에 옮길 수 있습니다.

## 파일 구성

| 파일 | 역할 |
| --- | --- |
| `index.html`, `styles.css`, `app.js` | 화면과 동작 |
| `store.js` | 저장 담당(Firebase 또는 로컬) |
| `theme.js` | 색상(RGB) 설정 계산·적용 |
| `music.js` | 타이머 알람 음악(이 기기에 저장) |
| `config.js` | **Firebase 설정을 붙여 넣는 곳** — 여기만 직접 고치면 됩니다 |
| `sw.js` | 오프라인 캐시(서비스 워커) |
| `vendor/firebase.js` | Firebase JS SDK 12.19.0 중 필요한 부분만 묶은 파일 |
| `manifest.webmanifest`, `icons/` | 홈 화면 설치용 정보와 아이콘 |
| `firestore.rules` | Firestore 보안 규칙(콘솔에 붙여 넣을 내용) |

## 주요 기능

- **오늘**: 하루 과제를 여러 개 넣고 왼쪽 손잡이(⠿)를 끌거나 ↑↓로 우선순위 정하기(과제마다 '뭘 할지' 메모, 맨 위의 끝나지 않은 과제는 '지금 할 과제'가 되어 시작 시점을 선택해서 적을 수 있음), 못 끝낸 과제 '내일로 넘기기'(설정에서 켜 두면 앱을 열 때 지난날 남은 과제가 자동으로 오늘 목록 맨 아래로 옮겨짐), 10분 시작 타이머(누르는 순간 '시작함' 기록), 내일 과제 미리 정하기
- **과제 세분화**: 과제마다 '단계' 체크리스트(진행도 표시, 지금 할 과제의 다음 단계는 미션 창에도 표시). 며칠째 넘어오는지 표시하고, 4일째부터 '단계로 쪼개기 / 다시 정하기 / 버리기' 안내
- **시간표**: 설정의 '고정 일과'(수업·자습 등, 요일별)와 과제의 '할 시간'으로 오늘 타임라인을 만들고, 빈 시간이나 고정 일과의 '+ 넣기'를 눌러 과제를 넣음(일과 안에 넣은 과제는 그 일과 아래에 묶여 보이고, 남은 시간도 표시). 할 시간의 시작 시각에 자동 알림(구글 캘린더에는 시작~끝 일정). 다음 날로 넘어간 과제는 할 시간이 비워짐
- **공부 시작 체크리스트**: 시작 타이머·타이머 탭·'타이머 없이 시작했어요'를 누를 때마다 확인 항목을 띄움(설정에서 항목 편집·끄기, 미션 창에서 시작할 때는 생략)
- **공부 플레이리스트**: 음악 카드의 '공부 플레이리스트' 탭. 어느 타이머든 돌 때만 재생되고 멈추면 같이 멈춤(알람 음악과 따로 저장)
- **과제 마감일(선택)**: 과제를 추가할 때나 편집에서 마감일을 정하면 목록에 '내일 마감', 'D-6', '마감 2일 지남'처럼 표시되고, 다가오는 일정·주·달 화면·미션 창·알림(전날/당일)·구글 캘린더에도 들어감. 마감일이 없는 과제는 기존처럼 동작
- **주·달**: 주간 결과물, 요일별 과제, 시작한 날이 칠해지는 연속 기록 달력
- **장기 과제**: 공식 마감에서 거꾸로 계산한 중간 지점 자동 배치
- **타이머**: 기존 Personal-Timer 기능(카운트다운, +1/5/10/30/60분, 알람·알림, 새로고침 복원, 미니 창, 알람 음악)을 옮겨 옴. 끌 때마다 그날 집중 시간에 기록할지 물어봄. 미니 창은 '미션 창'으로 바뀜: 오늘 과제 전체(끝낸 과제는 줄 긋기, 눌러서 완료 체크), 장기 과제마다 다음 단계와 D-day, 아래에 작은 타이머. 오늘 화면과 타이머 화면의 '미션 창' 버튼으로 열고, 크롬북 등 데스크톱 크롬 계열에서만 지원(브라우저 정책상 한 번에 하나만 열림)
- **알림**: 과제마다 '알림 시각', 장기 과제 중간 지점·공식 마감은 설정에서 고른 시각(전날/당일)에 알림. 앱이 열려 있으면 앱 안 알람(소리·알림 창·기기 알림)이 울리고, 구글 캘린더를 연결하면 '학업 플래너' 캘린더에 일정이 자동으로 들어가 앱이 꺼져 있거나 오프라인이어도 캘린더 앱이 알려 줌. 타이머 종료 시각도 캘린더에 들어감(시작할 때 온라인이고 연결이 살아 있을 때)
- **설정**(오른쪽 위 톱니): 앱 전체 색상을 프리셋 또는 RGB로 지정(기기 간 동기화), 시작 타이머 길이, 백업

## 1. GitHub Pages에 올리기

1. GitHub에서 새 저장소를 만듭니다(예: `study-planner`, Public).
2. 이 폴더의 파일을 **폴더 구조 그대로** 업로드합니다(`icons/`, `vendor/` 폴더 포함).
3. 저장소의 **Settings → Pages**에서 Source를 `Deploy from a branch`, 브랜치를 `main`, 폴더를 `/ (root)`로 정하고 저장합니다.
4. 1~2분 뒤 `https://아이디.github.io/study-planner/` 주소가 열리면 완료입니다. 이 상태에서는 로컬 모드로 동작합니다.

## 2. Firebase 프로젝트 만들기

1. [Firebase 콘솔](https://console.firebase.google.com/)에서 개인 구글 계정으로 **프로젝트 추가**를 누르고 이름을 정합니다. 구글 애널리틱스는 꺼도 됩니다.
2. 프로젝트 개요 화면에서 **웹(`</>`) 아이콘**을 눌러 앱을 등록합니다. 앱 닉네임만 적고, Firebase Hosting 설정은 체크하지 않습니다.
3. 화면에 나오는 `const firebaseConfig = { ... };` 부분을 복사해 둡니다(5단계에서 씀).

요금제는 무료(Spark)로 충분합니다. 결제 수단을 등록할 필요가 없습니다.

## 3. 로그인 켜기

1. 왼쪽 메뉴 **빌드 → Authentication → 시작하기**.
2. **로그인 방법** 탭에서 **이메일/비밀번호**를 선택해 사용 설정하고 저장합니다(이메일 링크는 끈 채로 둡니다).
3. (권장) **설정 → 승인된 도메인**에 `아이디.github.io`를 추가합니다. 이메일/비밀번호 로그인만 쓸 때는 필수가 아니지만, 나중에 다른 로그인 방식을 붙일 때 필요합니다.

> 구글 로그인 대신 이메일/비밀번호를 쓴 이유: Firebase 호스팅이 아닌 곳(GitHub Pages)에 올린 PWA를 아이패드 홈 화면 앱으로 쓸 때, 구글 로그인 팝업·리디렉션이 불안정한 경우가 알려져 있기 때문입니다. 이메일/비밀번호는 이런 문제가 없습니다.

## 4. 데이터베이스(Firestore) 만들기

1. **빌드 → Firestore Database → 데이터베이스 만들기**.
2. 위치는 `asia-northeast3 (서울)`을 고릅니다. **위치는 나중에 바꿀 수 없습니다.**
3. **프로덕션 모드**로 시작합니다.
4. 만들어지면 **규칙** 탭을 열고, 기존 내용을 지운 뒤 `firestore.rules` 파일 내용을 그대로 붙여 넣고 **게시**합니다.

이 규칙은 "로그인한 본인만 자기 데이터를 읽고 쓸 수 있다"는 뜻이며, 이후 기능이 추가되어도 고칠 필요가 없습니다.

## 5. config.js에 설정 붙여 넣기

1. GitHub 저장소에서 `config.js`를 열고 연필(편집) 버튼을 누릅니다.
2. 맨 아래 `export const firebaseConfig = null;`의 `null` 자리를 2단계에서 복사한 `{ ... }` 객체로 바꿉니다. 결과는 아래 모양이어야 합니다.

```js
export const firebaseConfig = {
  apiKey: "...",
  authDomain: "...",
  projectId: "...",
  storageBucket: "...",
  messagingSenderId: "...",
  appId: "..."
};
```

3. **Commit changes**로 저장합니다. 1~2분 뒤 Pages에 반영됩니다.

`apiKey`는 이름과 달리 비밀번호가 아니라 프로젝트를 가리키는 공개 식별자라서 공개 저장소에 올라가도 괜찮습니다. 데이터 보호는 4단계의 보안 규칙이 담당합니다.

## 6. 기기마다 설치하고 로그인하기

앱 주소를 연 뒤 첫 기기에서 **계정 만들기**, 다른 기기에서는 같은 이메일로 **로그인**합니다. 첫 로그인은 인터넷이 연결된 상태에서 해야 합니다.

- **크롬북**: 크롬 주소창 오른쪽의 설치 아이콘(또는 메뉴 → 앱 설치).
- **아이패드·아이폰**: 사파리로 열고 공유 버튼 → **홈 화면에 추가**. 홈 화면 아이콘으로 실행해야 앱처럼 동작하고 오프라인 저장도 안정적입니다.
- **안드로이드**: 크롬 메뉴 → **앱 설치** 또는 **홈 화면에 추가**.

## 7. 오프라인 확인

온라인에서 앱을 한 번 연 뒤 비행기 모드로 바꾸고 다시 열어 보세요. 상단 표시가 '오프라인'으로 바뀌고, 그 상태에서 입력한 내용은 기기에 저장되었다가 다시 연결되면 '동기화 대기' → '동기화됨'으로 바뀌며 서버에 올라갑니다.

같은 항목을 두 기기에서 오프라인으로 각각 고쳤다면, 나중에 저장된 쪽이 남습니다.

## 업데이트하는 방법

바뀐 파일을 GitHub 저장소에 덮어써서 커밋하면 됩니다. 앱은 온라인일 때 항상 새 파일을 먼저 받아 오므로, 다음에 온라인 상태로 열 때 반영됩니다. 새 파일을 추가했다면 `sw.js`의 `SHELL` 목록에도 넣고, 맨 위 `VERSION` 값을 올려 주세요(예: `v1.0.1`).

`config.js`는 업데이트할 때 덮어쓰지 않도록 주의하세요. 덮어썼다면 5단계를 다시 하면 됩니다.

## 선택: 다른 사람의 가입 막기

지금 규칙으로도 다른 사람은 내 데이터를 볼 수 없지만, 앱 주소를 아는 사람이 계정을 만들어 자기 데이터를 저장하는 것까지 막지는 않습니다. 완전히 혼자 쓰고 싶다면 내 계정을 만든 뒤 **Authentication → 사용자** 목록에서 내 `사용자 UID`를 복사하고, 규칙의 조건을 아래처럼 바꿔 게시하세요.

```
allow read, write: if request.auth != null && request.auth.uid == uid && uid == "내_UID";
```

## 문제가 생겼을 때

| 증상 | 확인할 것 |
| --- | --- |
| 로그인할 때 "이메일/비밀번호 로그인이 켜져 있는지 확인" | 3단계 |
| "동기화 권한이 없습니다" 배너 | 4단계 규칙을 붙여 넣고 **게시**했는지 |
| 계속 '로컬 모드'로 나옴 | `config.js`가 제대로 저장됐는지, 몇 분 기다린 뒤 새로고침 |
| "앱 구성 요소를 불러오지 못했습니다" | 처음 한 번은 온라인에서 열어야 오프라인용 파일이 저장됨 |
| 업데이트가 안 보임 | 온라인 상태에서 앱을 완전히 닫았다가 다시 열기 |

## 저장 구조(기능 추가 시 참고)

모든 기록은 `users/{내 UID}/` 아래에 저장됩니다.

- `days/{YYYY-MM-DD}` — 그날의 과제 목록 `tasks`(배열 순서가 우선순위, 과제마다 이름·'뭘 할지' 메모(memo)·완료·연결된 장기 과제, 맨 위 과제의 시작 시점(cue)), 시작 여부, 집중 시간(분). v1.1 이전의 단일 과제(`task` 등)는 1순위 과제로 읽힘
- `projects/{id}` — 장기 과제 이름, 시작일, 공식 마감, 여유 기간, 단계 목록
- `weeks/{그 주 월요일 날짜}` — 주간 결과물 목록
- `meta/settings` — 타이머 길이 등 설정

타이머 진행 상태와 알람 음악은 기기마다 따로 저장됩니다(한 기기에서 시작한 타이머가 다른 기기에 뜨지는 않음). 시작 기록, 집중 시간, 색상 설정은 동기화됩니다.

## 구글 캘린더 연결(선택)

앱 안 알람은 설정 없이 동작합니다. 앱이 꺼져 있거나 오프라인일 때도 알림을 받으려면 아래를 한 번 해 두세요. Firebase 프로젝트가 그대로 Google Cloud 프로젝트이므로 같은 프로젝트에서 진행합니다.

1. [Google Cloud 콘솔](https://console.cloud.google.com/)에서 위쪽 프로젝트 선택을 Firebase 프로젝트(planerr-…)로 바꿉니다.
2. **API 및 서비스 → 라이브러리**에서 `Google Calendar API`를 검색해 **사용**을 누릅니다.
3. **Google 인증 플랫폼(Google Auth Platform)**에서 시작하기: 앱 이름(예: 학업 플래너), 지원 이메일(본인), 대상은 **외부(External)**, 연락처 이메일을 넣고 만듭니다.
4. **대상(Audience)** 화면의 **테스트 사용자**에 캘린더를 쓸 본인 Gmail을 추가합니다. 게시 상태는 '테스트'로 둡니다.
5. **클라이언트(Clients) → 클라이언트 만들기**: 유형은 **웹 애플리케이션**, **승인된 JavaScript 원본**에 `https://eian337.github.io`를 넣습니다(끝에 `/`나 경로 없이). 만들고 나오는 **클라이언트 ID**(`….apps.googleusercontent.com`)를 복사합니다.
6. `config.js`의 `googleClientId = ''` 따옴표 안에 클라이언트 ID를 넣습니다.
7. 앱의 설정 → 구글 캘린더 → **구글 캘린더 연결**. 개인용 앱이라 '확인되지 않은 앱' 경고가 한 번 뜹니다. **고급 → (앱 이름)(으)로 이동**을 누르고 캘린더 권한을 허용하면 됩니다.

연결하면 구글 캘린더에 '학업 플래너' 캘린더가 생기고, 플래너가 다루는 권한(`calendar.app.created`)은 이 캘린더와 그 일정뿐입니다. 연결 권한은 1시간 정도면 만료되며, 만료된 뒤 바뀐 내용이 있으면 상단에 📅 표시가 뜨고 누르면 반영됩니다. 휴대폰·아이패드에는 구글 캘린더 앱(또는 구글 계정을 연결한 기본 캘린더 앱)에서 '학업 플래너' 캘린더 알림을 켜 두세요. 오프라인 알림은 일정이 미리 그 기기로 동기화되어 있어야 옵니다.
